# Two Sum – Unique Pairs

## Problem Statement

Given an array of integers `nums` and an integer `target`, return **all unique pairs** `(a, b)` such that:

```
a + b == target
```

### Constraints and Rules

* Each pair must be **unique** (e.g. `(2, 3)` and `(3, 2)` are the same pair)
* Order of pairs does **not matter**
* Each number can be used **only as many times as it appears**
* Result should not contain duplicates


## Example

```python
nums = [1, 2, 3, 4, 3, 2]
target = 5
```

### Output

```text
[(1, 4), (2, 3)]
```

## Approach 1: Brute Force (Nested Loops)

### Idea

* Check every possible pair
* Ensure uniqueness by sorting pairs and storing them in a set

### Code

```python
def two_sum_unique_bruteforce(nums, target):
    result = set()
    n = len(nums)

    for i in range(n):
        for j in range(i + 1, n):
            if nums[i] + nums[j] == target:
                pair = tuple(sorted((nums[i], nums[j])))
                result.add(pair)

    return list(result)
```

### Complexity

* Time: **O(n²)**
* Space: **O(k)** (number of unique pairs)

### Pros / Cons

* Simple and intuitive
* Very slow for large inputs


## Approach 2: Hash Set (Most Common and Efficient)

### Idea

* Iterate once through the list
* Track seen numbers in a set
* For each number `x`, check if `target - x` already exists
* Store pairs in a set to avoid duplicates

### Code

```python
def two_sum_unique_hashset(nums, target):
    seen = set()
    pairs = set()

    for num in nums:
        complement = target - num
        if complement in seen:
            pairs.add(tuple(sorted((num, complement))))
        seen.add(num)

    return list(pairs)
```

nums = [1, 2, 3, 4, 3, 2]
target = 6

| Step | num | complement | seen before | pairs            |
| ---- | --- | ---------- | ----------- | ---------------- |
| 1    | 1   | 5          | ❌           | {}               |
| 2    | 2   | 4          | ❌           | {}               |
| 3    | 3   | 3          | ❌           | {}               |
| 4    | 4   | 2          | ✅           | {(2, 4)}         |
| 5    | 3   | 3          | ✅           | {(2, 4), (3, 3)} |
| 6    | 2   | 4          | ✅           | {(2, 4), (3, 3)} |


### Complexity

* Time: **O(n)**
* Space: **O(n)**

### Pros / Cons

*  Fast and clean
*  Best choice for interviews
*  Uses extra memory


## Approach 3: Two Pointers (After Sorting)

### Idea

* Sort the array
* Use two pointers (`left`, `right`)
* Move pointers inward based on sum
* Skip duplicates to ensure uniqueness

### Code

```python
def two_sum_unique_two_pointers(nums, target):
    nums.sort()
    left, right = 0, len(nums) - 1
    result = []

    while left < right:
        s = nums[left] + nums[right]

        if s == target:
            result.append((nums[left], nums[right]))
            left += 1
            right -= 1

            while left < right and nums[left] == nums[left - 1]:
                left += 1
            while left < right and nums[right] == nums[right + 1]:
                right -= 1

        elif s < target:
            left += 1
        else:
            right -= 1

    return result
```

### Complexity

* Time: **O(n log n)** (sorting)
* Space: **O(1)** (excluding output)

### Pros / Cons

* No extra hash structures
* Scales well
* Requires sorting (modifies input)

## Comparison Summary

| Approach     | Time       | Space | Notes                     |
| ------------ | ---------- | ----- | ------------------------- |
| Brute Force  | O(n²)      | O(k)  | Educational only          |
| Hash Set     | O(n)       | O(n)  | Best for interviews       |
| Two Pointers | O(n log n) | O(1)  | Best when sorting allowed |


## Example Test

```python

```
